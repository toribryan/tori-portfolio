Data table is one table for every list people work through. Selection is
always the first column, every action lives in one toolbar above the rows,
and the same parts hold up from a wide dashboard down to a phone.

<Exhibit
  of="data-table.Default"
  title="Data table"
  description="Select a row. The toolbar swaps in place to the count and bulk actions. Shift-click selects a range, and Escape clears."
>
<ExhibitCode label="Install">

```bash
npx shadcn@latest add https://fibo.toribryan.com/r/data-table.json
```

It brings Table, Checkbox, Avatar, Tooltip, Button, Menu and Sheet with it.

</ExhibitCode>
<ExhibitCode label="Usage">

```tsx
import { Badge } from "@/components/ui/badge"
import {
  DataTable,
  DataTableBody,
  DataTableCell,
  DataTableContent,
  DataTableHead,
  DataTableHeader,
  DataTableRow,
  useDataTableSelection,
} from "@/components/ui/data-table"

export function Members({ members }: { members: Member[] }) {
  const selection = useDataTableSelection()
  return (
    <DataTable
      aria-label="Members"
      rowIds={members.map((member) => member.id)}
      noun={{ one: "member", other: "members" }}
      {...selection}
    >
      <DataTableContent>
        <DataTableHeader>
          <DataTableHead type="person" pinned="start">
            Member
          </DataTableHead>
          <DataTableHead type="status">Status</DataTableHead>
        </DataTableHeader>
        <DataTableBody>
          {members.map((member) => (
            <DataTableRow
              key={member.id}
              id={member.id}
              lockedReason={
                member.isOwner
                  ? "The workspace owner can't be removed"
                  : undefined
              }
            >
              <DataTableCell
                type="person"
                pinned="start"
                avatar={{ src: member.photo, fallback: member.initials }}
              >
                {member.name}
              </DataTableCell>
              <DataTableCell type="status">
                <Badge variant="success">{member.status}</Badge>
              </DataTableCell>
            </DataTableRow>
          ))}
        </DataTableBody>
      </DataTableContent>
    </DataTable>
  )
}
```

Give each head the same `type` and `pinned` as its column's cells. The first
column is primary or person, because its text names the row's checkbox. The
table only ever holds one page: the app sorts, filters and pages its own data.

</ExhibitCode>
<ExhibitCode label="Props">

| Prop                       | Type                             | Default     | Description                                                             |
| -------------------------- | -------------------------------- | ----------- | ----------------------------------------------------------------------- |
| `rowIds`                   | `string[]`                       |             | The ids of the rows on this page, in the order they're shown.           |
| `value`                    | `Set<string> \| "all"`           |             | The selection. `"all"` means every matching row, on every page.         |
| `defaultValue`             | `Set<string> \| "all"`           | `new Set()` | The selection to start with when it isn't controlled.                   |
| `onValueChange`            | `(value) => void`                |             | Called with the new selection.                                          |
| `totalCount`               | `number`                         | rows shown  | How many rows match across every page, for Select all matching.         |
| `noun`                     | `{ one: string; other: string }` | rows        | What a row is, for counts and labels.                                   |
| `narrowLayout`             | `"scroll" \| "cards"`            | `"scroll"`  | Under 32rem, keep the table and scroll it, or show a card per row.      |
| `showSelectedOnly`         | `boolean`                        | `false`     | Whether the app is showing only the selected rows.                      |
| `onShowSelectedOnlyChange` | `(show: boolean) => void`        |             | Shows Show selected only while rows are selected. The app filters rows. |

Head and Cell take `type` (primary, text, person, status, numeric, actions)
and `pinned` (none, start, end). Cell also takes `secondary`, `icon` and
`avatar`. Row takes `id` and `lockedReason`.

</ExhibitCode>
</Exhibit>

## Anatomy

A native table inside a box that measures its own width. The toolbar sits
above it, and the cards replace it on a narrow screen.

<Exhibit

<ExhibitCode label="Structure">

```text
DataTable                 data-table
├─ DataTableToolbar       data-table-toolbar
│  ├─ DataTableFilters    data-table-filters      (idle)
```

### Bulk actions

Every table's bulk actions read in one order: your actions, then More, then
Delete behind a divider. An action that works on one row stays in place,
dimmed, while more are selected.

<Exhibit of="data-table.BulkActionPatterns" title="Bulk action patterns">
<ExhibitCode>

```tsx
<DataTableBulkActions
  onDelete={remove}
  moreActions={<MenuItem>Resend invite</MenuItem>}
>
  <DataTableBulkAction>Change role</DataTableBulkAction>
  <DataTableBulkAction single icon={<PencilIcon />}>
    Edit
  </DataTableBulkAction>
</DataTableBulkActions>
```

</ExhibitCode>

### Across pages

Select the page, and the toolbar offers every matching row. Show selected

### On a phone

Under 32rem of its own width, the table scrolls under an icon-only toolbar,
or each row becomes a card. Sort and filters move into a sheet.

<ExhibitGrid>
<Exhibit of="data-table.NarrowScroll" title="Scroll">
<ExhibitCode>

```tsx

```

</ExhibitCode>
</Exhibit>
