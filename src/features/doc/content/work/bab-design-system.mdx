## Two artefacts, one product

The [Support Agent Dashboard](/work/support-agent-dashboard) shipped as a
25-screen clickthrough: vanilla HTML, CSS and JavaScript, no framework, no build
step. Right shape for proving an interaction, wrong shape for handing to
engineering, since a prototype has no components in it. It has markup that
happens to look like components.

This is the other half: the same product expressed as a library.

Two reds, one meaning each. `--primary` (`oklch(0.525 0.211 18.9)`) carries
every primary action. `--red-deep` (`oklch(0.484 0.194 18.7)`) is reserved for
the inbox Close button and the live-attempt badge, and nothing else. A single `--red` would have blurred two
meanings into one swatch, and they'd have drifted apart in code anyway.

Badge and button labels sit at normal weight. Bold is a signal, and in this
product it belongs to unread rows and headings, not to every control.

## Icons

One library, one weight. Every glyph is Lucide, and every glyph is drawn at a
1.5 stroke that scales with the icon, so a 12px check in a stat tile and a
40px robot on a source card keep the same stroke-to-size ratio and read as the
same family. The stroke is set once, in a provider the app shell wraps, and
never at a call site.

## The token layer is the deliverable

The prototype already had a disciplined `tokens.css`: surfaces, chat row
states, a series palette for charts. Rather than redraw those decisions in
Tailwind's vocabulary, the rebuild promotes them into a `@theme` layer under the
same names, so a value never means one thing in the clickthrough and another in
the React build.

```css title="src/index.css"
:root {
  /* the one red that means "primary action" */
  --primary: oklch(0.525 0.211 18.9);
  /* app ground: cards float on it, no dividers */
  --background: oklch(0.945 0.004 39.5);
  /* tiles and chart wells inside a white card */
  --surface-nested: oklch(0.977 0.002 67.8);
  /* selected chip, filter pill, received bubble */
  --sel: oklch(0.873 0.009 34.3);

  /* Inbox rows carry their own scale, because "unread" has to read as
     lighter than the ground while "read" reads as a step darker. */
  --unread: oklch(0.992 0.001 17.2);
  --chat-read: oklch(0.913 0.006 31.1);
}
```

Every one of those tokens has a dark counterpart, so the warm grey ground, the
inbox row scale and the role pairs all survive a theme switch, and the brand red
stays red rather than falling back to a stock white primary. The two blocks
live inside a managed region, so a token sync from Figma writes there and
nowhere else.

### Role pairs

The chart series reuse these hues, so a colour carries one meaning across the
whole product.

| Role       | Background                 | Foreground                 |
| ---------- | -------------------------- | -------------------------- |
| Student    | `oklch(0.924 0.035 52.0)`  | `oklch(0.544 0.160 40.1)`  |
| Instructor | `oklch(0.932 0.032 255.6)` | `oklch(0.488 0.217 264.4)` |
| Admin      | `oklch(0.947 0.082 95.6)`  | `oklch(0.666 0.157 58.3)`  |

### Status

| Token           | Value                      | Use                                     |
| --------------- | -------------------------- | --------------------------------------- |
| `--success`     | `oklch(0.508 0.105 165.6)` | Resolved, healthy, within threshold     |
| `--warning`     | `oklch(0.555 0.146 49.0)`  | Approaching a threshold                 |
| `--destructive` | `oklch(0.583 0.239 28.5)`  | Failed check, above threshold           |
| `--readonly`    | `oklch(0.631 0.047 256.0)` | Fields the agent can see but not change |

### Inbox row states

The one place the palette gets fussy, because three states have to be
distinguishable at a glance down a long list. Unread reads _lighter_ than the
ground; read reads a step darker; selected gets its own warm grey rather than
borrowing `--sel`.

| State    | Rest                      | Hover                     |
| -------- | ------------------------- | ------------------------- |
| Unread   | `oklch(0.992 0.001 17.2)` | `oklch(0.958 0.005 34.3)` |
| Read     | `oklch(0.913 0.006 31.1)` | `oklch(0.880 0.007 39.5)` |
| Selected | `oklch(0.840 0.012 31.1)` | `oklch(0.799 0.015 33.1)` |

### Type

Geist Variable throughout: `--font-heading` is an alias of `--font-sans`, not a
second family. Headings differentiate by weight and size against Tailwind's
default scale; there is no bespoke scale to memorise, and no component reaches
for an off-scale size to get there.

### Radius

One base, everything else derived. Changing `--radius` reshapes the product.

```css
--radius: 0.75rem; /* lg */
--radius-sm: calc(var(--radius) * 0.6);
--radius-md: calc(var(--radius) * 0.8);
--radius-xl: calc(var(--radius) * 1.4);
--radius-2xl: calc(var(--radius) * 1.8);
```

### Elevation

```css
--shadow-card: 0 0 4px rgba(0, 0, 0, 0.15);
```

That is the entire elevation system for surfaces. The content card is the only
shadowed surface on a page; anything nested inside it uses `--surface-nested`
with a hairline border. Floating layers, menus, popovers and the command list,
share one popover treatment and are the only other thing that casts a shadow.
A second shadow on a surface is a bug.
