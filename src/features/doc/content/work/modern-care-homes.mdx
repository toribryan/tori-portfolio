## Two people, one search

Modern Care Homes is a senior living marketplace for the Phoenix metro.
Families search independent and assisted living homes across six cities,
compare them, and contact a home directly. Agents list and manage those homes
on a second product, the agent platform.

<Plate background="none" caption="The grid families land on after a search.">
  <Video src="/case-studies/home-grid-mch.mp4" />
</Plate>

Two very different people use the marketplace for the same task, and neither
has patience for an interface that gets in the way.

<Sides>
<Side label="Their adult child" title="On a phone, short on time">

- Often in the middle of something stressful
- Comparing six homes to find cost and care level fast

</Side>
<Side label="The resident" title="Usually over 70">

- On a tablet or a desktop, with the browser zoomed way in
- Deciding whether a place looks like somewhere they could live

</Side>
</Sides>

Both stall at the same step. The flow is search, compare, contact, and families
are mostly ruling homes out, so compare is where I put the work.

## Studying the marketplaces that already solved it

Senior living is a marketplace problem first and a healthcare problem second,
so I study real estate marketplaces, not other care sites.

<Sides>
<Side label="Marketplace" title="Real estate search, in Mobbin">

- Filters, result density, map and list views
- Saved homes, and what a card shows at a glance
- What doesn't carry over: we filter by care level, and the person deciding often isn't the person moving in

</Side>
<Side label="Agent platform" title="Airbnb's listing flow">

- Mapped screen by screen, with Zillow's close behind
- What the host is doing, seeing and thinking at each stage
- What works, and where the openings are

</Side>
</Sides>

## What changed

### The home card shows what differs

The old card gave its widest line to marketing copy that read the same on every
listing. It didn't say whether a home had space, showed one photo, and gave
families no way to save a home. The new card leads with what separates one home
from the next.

<Plate caption="Before and after: an Available Now tag, a save button, a photo carousel, and the price under the name.">

### The agent dashboard is the listing

The old dashboard had two nav items and one long scroll, and many agents didn't
reach the end. Now each section of the listing sits in the sidebar with its own
state, so agents see what's thin before they open anything. That idea came from
the Airbnb study.

### Around the main screens

<Principles>
  <Principle title="The screens nobody screenshots">
    Filters, empty results and half-filled listings make up most real sessions,
    so I design them as carefully as the main screens.
  </Principle>
  <Principle title="Words families are still learning">
    Independent living, assisted living, levels of care. A page that assumes
    families know the difference has failed them.
  </Principle>
  <Principle title="A place, not a spreadsheet">
    I own the brand, type scale and photography, from marketing pages to search
    results, on a phone in a parking lot or a desktop at 200% zoom.
  </Principle>
</Principles>

## One design system, two products

Every component runs in both the marketplace and the agent platform, so a
change to a button changes two products.

<TwoJobs caption="Building the system, and using it in context. Hover a hub for a glimpse of each." />

### Tokens

Each color goes from a raw value, to a primitive named for what it is, to a
role named for its job. Components only ask for roles, and every role has a
Figma variable with the same name.

<TokenTiers />

### Components in Storybook

I build each component in <Tech name="storybook" /> first, in every state, at
every size and at 200% zoom. A component is ready when it works outside both
products. The library follows atomic design, so each new piece has to name its
level.

## The stack

| Tool                                             | Layer           | Why                                                                          |
| ------------------------------------------------ | --------------- | ---------------------------------------------------------------------------- |
| <Tech name="nextjs" />                           | Framework       | Server rendering, since much of the traffic is a phone on cell service.      |
| <Tech name="react" /> <Tech name="typescript" /> | UI              | TypeScript catches what I'd otherwise find in the browser.                   |
| <Tech name="tailwindcss" />                      | Styling         | Tokens live as CSS variables, so a system change is one edit.                |
| <Tech name="shadcn-ui" />                        | Components      | I own the source, so I fix accessibility issues inside the component.        |
| <Tech name="figma" />                            | Design          | Foundations and components, mapped one to one with the CSS variables.        |
| <Tech name="storybook" />                        | Components      | Every component, in every state, before it lands in either product.          |
| <Tech name="vercel" />                           | Deployment      | A preview build per branch, to check a change on a real phone.               |
| <Tech name="github" />                           | Version control | Design and code in one place.                                                |
| <Tech name="mobbin" />                           | Research        | Search and discovery patterns from real estate marketplaces.                 |
| <Tech name="posthog" />                          | Analytics       | Funnels for search, compare and contact, and replays of where families stop. |
