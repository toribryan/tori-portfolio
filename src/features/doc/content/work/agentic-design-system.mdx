## Where I started

After the [design system overhaul](/work/design-system-overhaul) at Proctorio,
engineers started generating code from designs and designers started
prototyping in code. Both used our system. Neither got it right, and nobody
knew why.

So I ran it as research with our lead front-end engineer. Same design, same
prompt, and the only thing I changed was how much of the system the model could
see.

## What I found

A model reads a design fine. It can't look at a rectangle and know it's your
Button. Left alone, it rebuilt components from scratch, hardcoded the colors it
could see, and combined parts in ways the system doesn't allow.

<Sides>
<Side label="Without usage instructions" title="Rebuilt from scratch">

{/* prettier-ignore */}
```tsx
<div
  className="rounded-md px-4 py-3
    bg-[#008b8b] text-white
    text-sm font-medium"
>
  Save changes
</div>
```

The hex is hardcoded and nothing links back to the system.

</Side>
<Side label="With Code Connect" title="Resolved to the component">

{/* prettier-ignore */}
```tsx
<Button
  variant="primary"
  size="sm"
>
  Save changes
</Button>
```

Variants and tokens come with it, so a rebrand just works.

</Side>
</Sides>

The information was in the system the whole time. The model just couldn't reach
it.

## What I built

Three fixes, all doing one thing: moving what the team knew into something a
model can read.

**Tokens.** The agent only sees semantic names like `color/action/primary`,
never raw values like `#008b8b`. Change one alias and everything follows.

contract, so the agent never has to guess.

That work grew into my [design skills
infrastructure](/latest/design-skills-infrastructure), which took spec
production from days to under 30 minutes.

## What was missing

Every fix was something I handed the agent. Nothing checked whether it listened.

## Where I am now

[fibo](/fibo) is my own design system, built with Claude Code. This time the
rules aren't just written down. They're enforced.

- Lint, format, Figma drift, build, types and tests run on every pull request.
- Every part installs into a fresh app before it ships.
- Every story runs an accessibility check that fails on any violation.
- A part missing its metadata fails the build.

It works. An agent recently added a voice memo component and the pull request
came in complete, with stories, docs, metadata, a changelog line and 396
passing tests. Nobody had to catch anything.

## What works today

Most public design systems now ship an MCP server and agent skills
([survey of 21](https://state-of-ai-in-design-systems.netlify.app/)). Here's
what actually moves the needle:

<Numbered>
  <Item title="Real components beat descriptions.">
    A registry of installable parts got agents to 95% compliance in a [CHI '26
    study](https://doi.org/10.1145/3772363.3798616).
  </Item>
  <Item title="Checks beat docs.">
    Agents opened rule files in 3.5% of runs, but followed rules 90 to 100% of
    the time once a check gave feedback
    ([RepoComplianceBench](https://arxiv.org/html/2607.26819v1)).
  </Item>
  <Item title="Small context beats big context.">
    A short index in AGENTS.md scored 100% in [Vercel's
    test](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals).
    Long overviews just cost more.
  </Item>
  <Item title="One name on both sides.">
    When Figma and code use the same token names, a script can catch drift.
  </Item>
</Numbered>
